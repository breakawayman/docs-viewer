# Markdown 文档查看器

把散落在文件夹里的 Markdown 文档整理成可浏览、可搜索、可导出的文档站点。基于 React、TypeScript 和 Vite，适合阅读技术笔记、项目说明和 API 文档。

支持直接读取项目中的 `docs/`，也可以在浏览器里选择计算机上的其他文件夹。无需后端、数据库服务或模型配置。

## 功能概览

| 功能 | 说明 |
| --- | --- |
| 多级文档目录 | 按文件夹自动生成目录树，支持展开、收起和记录展开状态 |
| 多目录切换 | 在项目文档与多个本地文件夹之间切换 |
| 全文搜索 | 在当前文档来源中匹配标题、路径和正文，不区分大小写 |
| 页内导航 | 根据 `#` 到 `####` 标题生成本页目录，点击跳转到对应章节 |
| Markdown 渲染 | 支持 GFM 表格、任务列表、删除线，以及代码高亮和代码复制 |
| Mermaid 图表 | 渲染图表，支持放大预览、缩放、拖动平移和适应窗口 |
| 主题与移动端 | 支持浅色、深色主题并记住选择；小屏幕通过菜单访问侧栏 |
| 文档导出 | 将当前文档打印为 PDF，或导出带样式和目录的 HTML 文件 |
| 开发时同步 | 项目文档及忽略规则变化后自动更新页面 |

## 快速开始

### 环境要求

- Node.js：`20.19+`（20.x）或 `22.12+`，推荐使用 Node.js 24 LTS。
- npm：随 Node.js 安装，项目已提供 `package-lock.json`。
- 浏览器：推荐最新版 Chrome 或 Edge；其他浏览器的本地目录能力取决于文件夹选择支持情况。

### 安装与启动

在项目根目录执行：

```bash
npm ci
npm run dev
```

打开 [http://localhost:5173](http://localhost:5173)，首页会进入 `/docs` 并打开第一篇可用文档。端口被占用时，Vite 可能选择其他端口，以终端输出为准。

启动后可以直接阅读 `docs/` 中的内容，也可以点击侧栏的“添加目录”选择自己的 Markdown 文件夹。修改依赖时可使用 `npm install` 更新依赖和锁文件。

开发和预览服务默认监听所有网络接口，同一局域网内可通过本机 IP 和实际端口访问。仅供本机使用时执行：

```bash
npm run dev -- --host 127.0.0.1
```

## 使用文档

### 选择文档来源

| 来源 | 内容来自哪里 | 如何更新 | 是否包含在部署产物中 |
| --- | --- | --- | --- |
| 项目目录 | 项目根目录下的 `docs/` | 开发时自动更新；部署后需重新构建发布 | 是，包含构建时收录的 Markdown 正文 |
| 本地目录 | 在浏览器中手动选择的文件夹 | 点击目录旁的刷新按钮 | 否，保存在当前浏览器中 |

`show/` 等其他项目目录不会自动收录，可以通过“添加目录”单独选择。

### 添加计算机上的文件夹

1. 点击左侧“文档位置”中的“添加目录”。移动端先打开左上角菜单。
2. 在系统选择器中选择文件夹，并允许读取。
3. 应用递归读取 `.md` 文件（扩展名不区分大小写），保留子目录结构。
4. 通过“文档位置”下拉框切换项目目录和已添加的本地目录。
5. 文件发生变化后，点击“刷新当前目录”；点击“移除当前目录”只移除浏览器中的记录，计算机上的文件会保留。

Chrome / Edge 在 `localhost` 或 HTTPS 环境下优先使用原生目录访问 API。其他支持文件夹选择的环境使用兼容模式：

- 原生模式保存目录句柄，刷新时可重新读取文件，必要时需要再次授权。
- 兼容模式保存文档快照，刷新时需要重新选择原目录，并按目录名称校验。多个同名目录可以分别添加，刷新时请自行确认选择的是原文件夹。
- 新添加的目录若没有可读取的 Markdown 文档，会显示提示。

本地目录记录、文档快照及可用的目录句柄保存在 IndexedDB 中。刷新页面、在同一浏览器中打开文档链接或新窗口导出 PDF 时，会自动恢复快照。网页不会自动监听这些文件夹的变化。

这些内容由浏览器读取和保存，应用不会将导入的 Markdown 正文上传到服务器。存储按网站来源隔离：更换协议、域名、端口或浏览器，以及清除网站数据后，都需要重新添加目录。本地文档链接也依赖该浏览器中的目录记录，不能直接作为共享文档链接使用。浏览器不提供所选文件夹的绝对路径，界面显示文件夹名称和文档相对路径。

### 浏览与搜索

- 在“文档目录”中选择文档；选择后，有可用标题的文档会切换到“本页目录”。
- 切回“文档目录”后，可以搜索标题、相对路径或 Markdown 正文。搜索范围是当前选择的来源，结果保留目录层级并自动展开。
- “本页目录”收录代码围栏以外的 `#`、`##`、`###`、`####` 标题。
- 点击主题按钮切换浅色或深色；首次访问会参考系统主题。

### Mermaid 图表

使用标记为 `mermaid` 的代码围栏即可绘制图表：

````markdown
```mermaid
flowchart LR
  A[选择目录] --> B[读取 Markdown]
  B --> C[浏览与搜索]
  C --> D[导出文档]
```
````

点击图表上的“放大查看”进入预览。支持滚轮或双指缩放、拖动平移；双击、按 `0` 或点击“适应窗口”可恢复适配，按 `Esc` 关闭。

### 导出当前文档

**PDF**：点击“导出 PDF”，应用会在新窗口打开打印页面并调用浏览器打印。在打印目标中选择“另存为 PDF”；如需去掉网址、日期等信息，关闭打印设置中的“页眉和页脚”。若未自动弹出打印对话框，可等待图表显示完整后再次点击打印页的“导出 PDF”。

**HTML**：点击“导出 HTML”，下载以文档标题命名的 `.html` 文件。导出结果保留当前深浅色主题，内嵌样式、代码高亮和预渲染的 Mermaid SVG，可直接用浏览器打开。图表以静态形式保留。

两种导出都针对当前一篇文档。HTML 导出不会打包图片和其他附件；外部资源仍依赖原地址是否可访问。

## 组织项目文档

### 目录、标题与排序

将 Markdown 文件放入项目根目录下的 `docs/`，无需手动维护导航配置。例如：

```text
docs/
├── 01-入门/
│   ├── 01-安装.md
│   └── 02-快速开始.md
├── 02-使用指南/
│   └── 01-配置说明.md
└── 常见问题.md
```

目录生成规则：

- 文件夹对应目录分组，Markdown 文件对应文档。
- 同一层级先显示文件夹，再显示文档；两类分别按数字前缀排序，没有前缀的排在后面，同序号再按标题进行中文本地化排序。
- 数字前缀支持 `01-`、`01_`、`01 ` 等格式，显示名称会去掉该前缀。
- 文档标题优先取正文中首个以 `# ` 开头的行；没有时使用去掉排序前缀的文件名。
- 路由保留原始目录名和文件名中的排序前缀，去掉 `.md` 扩展名，各路径段进行 URL 编码。

例如，`docs/01-入门/01-安装.md` 的侧栏分组显示为“入门”，文档地址为 `/docs/01-入门/01-安装`（浏览器可能显示为编码后的形式）。`README.md` 作为普通文档处理，不会自动成为所在目录的首页。

### 忽略不需要收录的内容

使用 `.docsignore` 控制文档目录、搜索和构建收录范围，语法与 `.gitignore` 相同，独立于项目的 `.gitignore`。

| 来源 | 读取哪个配置 | 规则相对路径 | 默认排除 |
| --- | --- | --- | --- |
| 项目 `docs/` | 项目根目录的 `.docsignore` | 项目根目录，如 `/docs/草稿/` | 随仓库配置排除 `.agent/`、`.agents/`、`.git/`、`node_modules/`；可编辑取消 |
| 浏览器本地目录 | 所选文件夹根部的 `.docsignore` | 所选文件夹，如 `/草稿/` | 固定跳过 `.git`、`.svn`、`node_modules`、`.npm-cache`、`.cache`，不可用规则重新包含 |

例如，在项目根目录的 `.docsignore` 中添加：

```gitignore
# 不收录草稿目录和所有以 .draft.md 结尾的文件
/docs/草稿/
*.draft.md

# 只保留归档目录中的说明文档
/docs/归档/*
!/docs/归档/说明.md
```

被忽略的父目录不会继续扫描，需要保留其中某个文件时，应像示例一样忽略目录内容。开发模式会自动响应项目根部忽略文件的创建、修改和删除；浏览器本地目录需要手动刷新。更完整的项目规则说明见 [DOCS_IGNORE.md](DOCS_IGNORE.md)。

### 图片、附件与链接

当前本地目录导入只读取 Markdown 文本，不会导入图片或其他附件，也不会为它们创建浏览器访问地址。正文中的相对图片地址和 `.md` 链接不会自动转换为所选文件夹中的资源或站内文档路由。

项目文档需要引用图片时，可将资源放在 `public/` 中，再使用网站根路径。例如，`public/images/example.png` 对应 Markdown 中的 `![示例](/images/example.png)`。需要链接到其他项目文档时，使用去掉 `.md` 后的 `/docs/...` 路由。外部资源使用可访问的完整 URL。

## 构建与部署

```bash
npm run build
npm run preview
```

`build` 先进行 TypeScript 项目构建检查，再生成 `dist/`；`preview` 用于在本地查看构建结果，默认地址同样为 [http://localhost:5173](http://localhost:5173)。

生产部署将 `dist/` 发布到静态托管服务即可。当前路由按网站根路径设计，托管服务需要支持 SPA 回退，让 `/docs/*` 和 `/local/*` 等页面路径返回 `index.html`。Nginx 配置示例：

```nginx
server {
    listen 80;
    server_name docs.example.com;
    root /var/www/docs-viewer/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

直接双击 `dist/index.html` 不能代替 HTTP 部署。若要部署在子路径下，需要同时调整 Vite 的 `base`、路由基路径及应用中的绝对路径，当前没有开箱即用的子路径配置。

项目 Markdown 正文会在构建时打包到前端资源中，发布前请通过 `.docsignore` 确认收录范围；忽略规则只控制收录，不提供访问权限控制。修改 `docs/` 或项目忽略规则后，需要重新构建并发布。本地目录仍由访问者在各自浏览器中添加。

## 常见问题

**添加目录后没有文档？** 确认选择的文件夹包含 `.md` 文件，且未被该文件夹根部的 `.docsignore` 或固定跳过规则排除。项目目录还需检查项目根部的 `.docsignore`。

**修改文件后页面没有变化？** `docs/` 在开发模式下自动同步；浏览器导入的目录需要点击刷新；已部署站点中的项目文档需要重新构建发布。

**本地目录读取失败或记录消失？** 检查网站是否允许使用 IndexedDB、是否有足够存储空间，以及目录读取权限是否仍有效。清除网站数据、更换浏览器或访问地址后需要重新添加。

**点击导出 PDF 没有反应？** 允许本站打开新窗口；如果打印页面已打开，点击其中的“导出 PDF”，并在浏览器打印对话框中选择保存为 PDF。

**文档页面刷新后出现 404？** 检查静态服务器是否将页面路由回退到 `index.html`，参考上面的 Nginx 示例。

**为什么本地图片或其他 Markdown 链接打不开？** 本地导入没有同步图片与附件，也没有改写相对链接。图片请使用可访问的资源地址，站内文档链接请使用应用路由。
